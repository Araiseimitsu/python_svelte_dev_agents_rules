# UI修正の検証

## 表示条件の再現

- 修正前と同じURL、認証状態、データ状態、表示幅を使う。
- コメント対象がスクロール後、モーダル内、hover時など特定状態にある場合は、その状態を再現する。
- 開発サーバーの再読み込み後も変更が残ることを確認し、ブラウザ内だけの一時変更でないことを確かめる。

## 視覚確認

- 各コメントの希望結果を一つずつ確認する。
- 対象外の近接要素に崩れがないか確認する。
- レイアウト変更では指定幅に加え、少なくとも近接する狭い幅または広い幅を確認する。
- interactiveな要素では、関連するhover、focus、disabledなどを必要に応じて確認する。
- 変更前後のスクリーンショットが利用可能なら比較するが、スクリーンショットだけを成功判定にしない。

## コード検証

プロジェクトに存在するコマンドから、変更に比例した検証を選ぶ。

- formatterまたは構文確認
- lint
- 型チェック
- 関連テスト
- production build

すべてを常に実行する必要はない。共通token、共有コンポーネント、ルート構造へ触れた場合は検証範囲を広げる。

既存エラーがある場合は、今回の変更前から存在したかを可能な範囲で区別する。無関係なエラーを黙って修正しない。

## 完了報告

次を簡潔に伝える。

- どのコメントをどう反映したか
- 主な変更ファイル
- 確認したURL、状態、表示幅
- 実行した検証と結果
- 確認できなかった状態または残るリスク
