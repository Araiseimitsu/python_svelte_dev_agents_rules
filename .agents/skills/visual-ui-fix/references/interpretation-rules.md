# 視覚指示をコードへ変換する規則

## 実装箇所の特定

一つの手掛かりだけで決めない。次を組み合わせて対象ソースを特定する。

- URLとルート定義
- 要素のタグ、表示文言、ARIA属性、テストID
- class、CSS Modules、CSS-in-JS、Tailwind utilities
- 親子構造と近接する固有文言
- フレームワークが開発時に提供するコンポーネント情報
- computed styleと、その値を生成している規則

生成された脆いselectorを恒久的な識別子としてソースへ追加しない。実装候補が複数ある場合は、それぞれの利用範囲を検索してから決める。

## 意味を保つ変換

| 視覚操作 | 優先する実装 | 避ける実装 |
|---|---|---|
| 色変更 | 既存CSS変数、テーマtoken、Tailwind設定 | 同等tokenがあるのに生の色値を重複追加 |
| 余白変更 | 親のgap、padding、既存spacing scale | DOM構造を無視した個別marginの積み重ね |
| 位置変更 | Flex/Gridの整列、順序、コンテナ制約 | 意図が不明なabsolute座標やtransform |
| サイズ変更 | min/max、流動幅、既存size scale | 一画面幅だけに合う固定値 |
| テキスト変更 | 文言の所有元、翻訳辞書、データ定義 | 描画後DOMだけの一時変更 |
| 領域コメント | 領域内の関係と希望結果をまとめて解釈 | 囲まれた全要素の無差別な再設計 |

ユーザーのドラッグ量やプレビュー値は意図を示す証拠として使う。レスポンシブなレイアウトでは、その値をそのまま絶対座標へ変換しない。

## コンポーネントと影響範囲

- ページ限定の要望では、共有コンポーネント全体を変える前に既存variant、props、局所的なcompositionで対応できるか確認する。
- 全体へ適用する意図が明確なら、重複した局所修正ではなくtokenまたは共有コンポーネントを変更する。
- hover、focus-visible、active、disabled、loading、dark modeが存在する場合は、通常状態との整合を保つ。
- 色変更では既存のコントラストを悪化させない。意図を変えずにtokenを選べない場合は、その不確実性を示す。
- 文言がデータや翻訳から来る場合は、表示箇所ではなく所有元を修正する。

## 変更の制約

- アプリのソースへOverlay、開発用data属性、依存パッケージを埋め込まない。CLI用Overlayはブラウザセッションへ一時注入し、再読み込みやセッション終了で消える状態に保つ。
- 指定されていない依存パッケージを追加しない。
- 無関係なリファクタリングやフォーマット変更を混ぜない。
- 一時プレビューと永続的なコード変更を区別する。
